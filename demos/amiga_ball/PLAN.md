# Amiga Ball Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A C64 demo in pure 6502 assembly in which a checkered, rotating,
hardware-sprite Boing Ball bounces in a perspective wire-grid room, drags a
shrinking contact shadow, and synthesises a distinguishable "boing" off the
floor and off the walls.

**Architecture:** One raster interrupt at line 10 does the whole per-frame job
through a single `tick` subroutine; the main loop only proves it is alive. All
art and all tables are generated by stdlib-only Python in `tools/` and committed
as `.byte` rows. The charset and sprite blocks are placed at fixed addresses by
`c64 build --area`; every observable byte lives in a third area at `$4000` so its
address is fixed rather than incidental.

**Tech Stack:** ca65/ld65 via `c64 build`, VICE via `c64` CLI, Python 3 stdlib
for the generators, `c64 test run` YAML for regression.

**Spec:** `demos/amiga_ball/SPEC.md` — read it first; this plan argues from it
and every task cites the section it implements.

## Global Constraints

Copied verbatim from `SPEC.md`. Every task's requirements implicitly include
these.

- **Build line** (all three areas, every build, every test, every package):
  `--area 'CHARS=$2000:$0800' --area 'SPRITES=$2800:$1800' --area 'VARS=$4000:$0100'`
- **Machine is NTSC** (`c64`, 60 Hz). The bounce table and the SID frequency
  constant `Fn = Hz × 16.40483` are both NTSC-only.
- **Sessions are `--warp --headless`.** Name the session `ball`
  (`c64 session ensure -s ball --warp --headless`). On macOS, any unattended
  detached run goes under `caffeinate -dimsu`.
- **`tick` is the frame anchor**, never `mainloop` — the main loop free-runs, so
  `until mainloop --count N` counts loops, not frames.
- **Nothing from ROM runs inside the interrupt.** The handler exits
  `pla / tay / pla / tax / pla / rti`, not via `$EA31` or `$EA81`.
- **Every SID write goes through `sidput`**, which mirrors it into
  `sid_shadow`. No bare `sta $D4xx` anywhere.
- **Every included `.s`/`.inc` file opens with an explicit `.segment`
  directive** — ca65 does not reset the active segment at file boundaries.
- **Generators are stdlib-only Python 3**, runnable standalone, and they
  **fail loudly** rather than emitting something short. Demo `tools/` scripts
  are outside the repo's `ruff`/`pyright` gates (AGENTS.md) but are still the
  demo's own tested artifact.
- **Graphics policy** (`docs/graphics-and-sprites.md`): art is committed as
  commented `.byte` rows; tests assert memory and registers and **never PNG
  pixels**; evidence PNGs are captured while the machine is stopped.
- **Comments state contracts, hardware quirks and non-obvious why**, and every
  claim in one carries the same evidence burden as a finding (AGENTS.md).

**`tools/gen_sprites.py` contract.**

- No arguments; writes `demos/amiga_ball/sprites.inc` relative to its own file.
- Constants at the top, named and commented: `TEXW=24`, `TEXH=42`,
  `SPH_TOP=3`, `SPH_ROWS=36`, `RX=12.0`, `RY=18.0`, `CX=12.0`, `CY=21.0`,
  `N_LON=16`, `N_LAT=8`, `FRAMES=16`, `SPAN_DEG=45.0`. (`CX`/`CY` are the
  block's *continuous* centre, not its index centre — spec §5.2 says what the
  index centre costs.)
- Per frame `f`: `rot = radians(SPAN_DEG * f / FRAMES)`. Per texel the ray cast
  and parity rule of spec §5.2, then the rim pass (inside-sphere texel with an
  outside 4-neighbour → pair `01`).
- Emits, per frame, four 64-byte blocks in the order **TL, TR, BL, BR**, where
  TL = texel cols 0-11 rows 0-20, TR = cols 12-23 rows 0-20, BL = cols 0-11
  rows 21-41, BR = cols 12-23 rows 21-41. Byte 63 of each block is `$00`
  padding so the next block stays 64-byte aligned.
- Output header comments must state: the pointer math `block = address / 64`,
  the first block number (160), and the pair→color legend.
- Label: `sprite_frames:` at the top, `sprite_frames_end:` at the bottom.
- **Asserts before writing:** total emitted length is exactly
  `FRAMES * 4 * 64 = 4096`; every frame contains at least one `10` pair and one
  `11` pair (the checkers exist); frame 0 and frame 8 differ (rotation is real).

### Task 2: The room

Spec: §4. **Parallel with T3, T4, T5.** Touches only `room.s`,
`tools/gen_room.py`, `chars.inc`, `screen.inc`.

**Files:**
- Modify: `demos/amiga_ball/room.s`
- Create: `tools/gen_room.py`
- Generate: `chars.inc`, `screen.inc`

**Interfaces:**
- Consumes: `room_init` (T1's stub), the `CHARS` and `RODATA` segments.
- Produces: `charset` / `charset_end` labels in `chars.inc`; `screen_map` /
  `screen_map_end` in `screen.inc`. `room_init` leaves the VIC configured and
  returns.

**`tools/gen_room.py` contract.**

- Constants at the top, each with the spec section it comes from:
  `WALL_ROWS=range(0,15)`, `HORIZON_ROW=15`, `FLOOR_ROWS=range(16,25)`,
  `WALL_VCOLS=[0,4,...,36]`, `WALL_HROWS=[0,3,6,9,12]`,
  `VP=(160,171)`, `DEPTH_K=79`, `DEPTHS=[1,2,3,4,5,6,8,10]`,
  `FAN_J=[-2,-1,0,1,2]`, `FAN_BOTTOM_SPACING=80`.
- Rasterises into a 320×200 1-bit canvas: wall verticals (1 px wide, full wall
  height), wall horizontals at rows 0/3/6/9/12 top scanline, the horizon at
  raster 171, floor depth lines at `171 + round(K/d)`, and floor fan lines
  `x(y) = 160 + j*(80/79)*(y-171)` for `y` in 171..250, clipped to 0..319.
- Slices the canvas into 8×8 cells, deduplicates the 8-byte patterns, forces
  the all-zero pattern to **code 0**, and assigns remaining codes in first-use
  order.
- Emits `chars.inc` (2,048 bytes — all 256 glyphs, unused ones zero, each glyph
  commented with its code and an ASCII picture of its 8 rows) and `screen.inc`
  (1,000 bytes, one commented line per screen row).
- **Asserts before writing:** glyph count ≤ 256 (print the actual count — it is
  the number the plan is betting on); `chars.inc` is exactly 2,048 bytes;
  `screen.inc` is exactly 1,000; at least one cell in each of rows 0, 15 and 20
  is non-zero.

**`room_init` contract.** Copies `screen_map` (1,000 bytes) to `$0400`; fills
`$D800`-`$DBE7` with `$04` for rows 0-14 and `$0E` for rows 15-24; writes
`$D011`=`$1B`, `$D016`=`$08`, `$D018`=`$18`, `$D020`=`$00`, `$D021`=`$00`.
It does **not** copy the character ROM — the charset is fully generated, so
there is no `$01` banking window to protect.

### Task 3: Motion — bounce, travel, rotation, and every sprite register

Spec: §5.3-5.4, §6, §7 (placement only), §9, §12. **Parallel with T2, T4, T5.**
Touches only `ball.s`, `tools/gen_bounce.py`, `bounce.inc`.

**Files:**
- Modify: `demos/amiga_ball/ball.s`
- Create: `tools/gen_bounce.py`
- Generate: `bounce.inc`

**Interfaces:**
- Consumes: every `VARS` label from T1; `sound_impact` (entry `A` = 1/2/3);
  block bases **160** (rotation frames, T1) and **224** (shadow shapes, T4).
- Produces: `ball_init`, `ball_step`, and the labels `bounce_tab` /
  `bounce_tab_end` in `bounce.inc`.

**`tools/gen_bounce.py` contract.** Emits `bounce_tab`: 64 entries of two bytes
(**fraction, integer** — 8.8 low byte first) for
`y(p) = 158 - 104*p*(64-p)/1024`, each line commented with `p` and the decimal
`y`. Asserts: exactly 128 bytes; `y(0)` integer = 158; `y(32)` integer = 54;
the sequence is symmetric about `p=32`; every integer is in 50..249.

**`ball_step` contract**, in this order:

1. If `freeze` is zero: advance `ball_x` (16-bit 8.8 `ball_xf`/`ball_xi` += signed
   `ball_vx`); if `ball_xi` would pass 0 or 223, clamp it to the bound, negate
   `ball_vx`, negate `spin_dir`, `inc wall_count`, set `last_impact` to 2 (left)
   or 3 (right), and `jsr sound_impact` with `A` = the same value. Then advance
   `bounce_phase`; on the wrap 63→0, `inc bounce_count`, set `last_impact` = 1,
   `jsr sound_impact` with `A` = 1. Then `rot_frame = (rot_frame + spin_dir) & 15`.
   Then `inc frame_count` (16-bit).
2. Always (whether frozen or not): `ball_yf`/`ball_yi` ← `bounce_tab[bounce_phase]`;
   `ball_x16` ← `24 + ball_xi` (16-bit); `shadow_x16` ← `ball_x16`;
   `shadow_size` ← the band of `158 - ball_yi` per spec §7.
3. Write the registers: `$D000`/`$D004` ← `ball_x16` low; `$D002`/`$D006` ←
   `(ball_x16 + 48)` low; `$D001`/`$D003` ← `ball_yi`; `$D005`/`$D007` ←
   `ball_yi + 42`; `$D008` ← `ball_x16` low, `$D00A` ← `(ball_x16+48)` low,
   `$D009` = `$D00B` = 225. Rebuild `$D010` **from scratch** (never
   read-modify-write): `$00` if `ball_xi < 184` else `$2A`.
4. Pointers: `$07F8+n` ← `160 + 4*rot_frame + n` for n=0..3, mirrored into
   `sptr`; `$07FC` ← `224 + 2*shadow_size`, `$07FD` ← `225 + 2*shadow_size`.

**`ball_init` contract.** `ball_xi`=40, `ball_xf`=0, `ball_vx`=`$01C0`,
`bounce_phase`=32, `rot_frame`=0, `spin_dir`=`$01`, `freeze`=0, all counters 0.
Sets `$D015`=`$3F`, `$D01C`=`$0F`, `$D017`=`$0F`, `$D01D`=`$3F`, `$D01B`=`$30`,
`$D025`=`$00`, `$D026`=`$01`, `$D027`-`$D02A`=`$02`, `$D02B`=`$D02C`=`$0B`.

### Task 4: The shadow art

Spec: §7. **Parallel with T2, T3, T5.** Touches only `tools/gen_shadow.py` and
`shadow.inc`. T3 owns where the shadow *goes*; this task owns what it *is*.

**Files:**
- Create: `tools/gen_shadow.py`
- Generate: `shadow.inc`

**Interfaces:**
- Produces: `shadow_shapes` / `shadow_shapes_end` in `.segment "SPRITES"`,
  linked **immediately after** `sprites.inc`, so its first block is 224.
- Consumed by T3 through the block numbers `224 + 2*size + half` only.

**`tools/gen_shadow.py` contract.**

- Constants: `SIZES = [(96,14),(80,12),(64,10),(48,8)]` (width in screen px,
  height in rasters), `PAIR_W = 96` (two X-expanded hires sprites), `ROWS = 21`,
  `CENTRE_ROW = 10`.
- **Hires**, not multicolor: 24 bits per sprite row, 48 texels across the pair,
  each texel 2 screen px wide after X-expansion.
- For each size, draws a filled ellipse of that width and height centred on
  (pair centre, `CENTRE_ROW`) into a 48×21 bit grid, then splits it into a left
  block (texels 0-23) and a right block (24-47), 63 bytes + 1 pad each.
- Emits 8 blocks in the order (size 0 left, size 0 right, size 1 left, …).
- **Asserts before writing:** exactly `4*2*64 = 512` bytes; each size's lit-bit
  count is strictly less than the previous size's (they really do shrink); every
  size is symmetric about the pair centre; row 10 of every size is the widest
  row.

- [ ] **Step 1: Write and run the generator**

Run: `python3 demos/amiga_ball/tools/gen_shadow.py`
Expected: 512 bytes; the four lit-bit counts printed and strictly decreasing.

### Task 5: The sound

Spec: §8. **Parallel with T2, T3, T4.** Touches only `sound.s`,
`tools/gen_sound.py`, `sound.inc`.

**Files:**
- Modify: `demos/amiga_ball/sound.s`
- Create: `tools/gen_sound.py`
- Generate: `sound.inc`

**Interfaces:**
- Consumes: `snd_timer`, `snd_kind`, `sid_shadow` (T1's VARS).
- Produces: `sidput`, `sound_init`, `sound_step`, `sound_impact`, and
  `cut_floor` / `cut_wall` (24 bytes each) in `sound.inc`.

**`tools/gen_sound.py` contract.** Emits two 24-byte tables: `cut_floor`
ramping 220→30 over entries 0-15 then holding 30, and `cut_wall` ramping
250→70 then holding 70. Each line commented with its frame index. Asserts:
24 bytes each; monotonically non-increasing; first and last values match the
spec table exactly.

**`sidput` contract.** `A` = value, `X` = register offset 0-24.
`sta $D400,x` then `sta sid_shadow,x`, `rts`. **Every** SID write in the demo
goes through it — a bare `sta $D4xx` anywhere is a defect, because the shadow is
the only evidence a stopped machine can give that sound happened.

**`sound_init` contract.** Zero all 25 registers through `sidput` (SID registers
survive a program stop and a left-over gate bit blocks a new note —
`references/hardware.md`), then write `$D417`=`$F2` (resonance 15, voice 2
routed) and `$D418`=`$1F` (low-pass + volume 15). Set `snd_timer` = 24 (idle).

**`sound_impact` contract.** `A` = 1 floor, 2/3 wall. Stores `snd_kind` (1 for
floor, 2 for either wall) and `snd_timer` = 0. Writes nothing to the SID itself
— `sound_step` does all of it, so the register schedule has exactly one author.

**`sound_step` contract.** If `snd_timer` ≥ 24, return. Otherwise, by timer
value:

| timer | writes |
|---|---|
| 0 | `$D405`=`$08`, `$D406`=`$00`, `$D40C`=`$04`, `$D40D`=`$00`; voice-1 freq `$0D`/`$07` (floor) or `$90`/`$0A` (wall) into `$D400`/`$D401`; voice-2 freq `$00`/`$10` (floor) or `$00`/`$18` (wall) into `$D407`/`$D408`; `$D404`=`$11`; `$D40B`=`$81` |
| 0-15 | `$D416` ← `cut_floor[timer]` or `cut_wall[timer]` |
| 20 | `$D404`=`$10`, `$D40B`=`$80` (gate off) |
| any | `inc snd_timer` |

### Task 7: The evidence protocol

Spec: §13.1, and `docs/graphics-and-sprites.md` §5's five rules.

**Files:**
- Create: `demos/amiga_ball/tools/evidence.sh`
- Generate: `demos/amiga_ball/evidence/*.png`, `*.txt`

**`evidence.sh` contract.** One `run`, then `until tick --count N` before every
capture; never `wait --mem/--text` straight after an `until`; stage unreachable
states by poking the demo's own bytes; `c64 call` (if used at all) only as the
final action before a capture; steal the two helpers verbatim:

```sh
C=".venv/bin/c64"; S="-s ballev"
shot()  { $C until tick --count 1 --timeout 120 $S >/dev/null    # flush, see below
          $C screen --png "$OUT/$1.png" --scale 2 --border $S >/dev/null; echo "  $1.png"; }
ticks() { $C until tick --count "$1" --timeout 120 $S >/dev/null; }
```

**The flush step is not optional and is not in the policy's five rules.**
`c64 screen --png` returns the emulator's rolling scanline buffer, not a
re-render of video RAM: lines the beam has already swept show the current
partial frame and lines below it show the *previous* one, which after a warped
or free-running phase is arbitrarily stale.
`demos/la-galaxia/tools/evidence.sh` learned this the hard way — its first
capture had boot-screen light blue below the beam — and states it as its own
rule 2. Stepping exactly one more tick immediately before the capture flushes
those lines. Do not optimise it away.

plus a third helper for this demo, because every visual claim here has a numeric
companion:

```sh
state() { $C mem read ball_xf 24 $S > "$OUT/$1.txt"; $C mem read '$07F8' 8 $S >> "$OUT/$1.txt"; }
```

`rot10`, `wall-left`, `wall-right`, `shadow-1`, `shadow-2`, `shadow-3`, and the
four `c64 sprite png` renders `ball-tl`, `ball-tr`, `ball-bl`, `ball-br` at one
rotation frame. Plus `sid-impact.txt` — the SID shadow on a floor-impact frame

**`tools/score.py` contract.** Reads the same constants as the demo — the
release frame of the staged impact inside the capture window, the 20-frame gate,
`A2`/`E3` — and writes the two score YAMLs. Voice 1 carries the notes; voice 3

transcription cannot fail and is therefore not evidence.

**Capture procedure.** Warp off, real time, ~42 ms of wall clock per frame plus
